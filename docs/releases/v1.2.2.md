## What's in 1.2.2

1.2.2 is a patch release of 1.2.1 with one fix. A multi-key write over a key past its TTL (`MSET`, `MSETNX`, `JSON.MSET`, or a `MULTI`/`EXEC` of plain `SET`s after `WATCH`) could make the whole server stop answering, `PING` included, until a restart, when a search index existed and was being changed at the same time. The write now lets go of all of its keys before it deletes the expired ones. Servers without a search index were not affected, and neither was 1.1.

## Security

1.2.2 fixes [GHSA-8rm8-p5c5-g3mr](https://github.com/kividbio/kividb/security/advisories/GHSA-8rm8-p5c5-g3mr) (medium): a multi-key write over a key past its TTL could make the whole server stop answering, until a restart, when a search index existed and was being changed at the same time. Any client allowed to run ordinary string and hash writes and one `FT.ALIAS*` command could trigger it; with a vector index and expiring hash fields, background work could too. Acknowledged writes were not lost. It affects 1.2.0 and 1.2.1; 1.1.x and servers without a search index are not affected. Upgrade to 1.2.2.

## Before you upgrade

Nothing new: 1.2.2 changes only this. What to check before upgrading from 1.2.0 or earlier is in the [1.2.1 release notes](https://github.com/kividbio/kividb/blob/v1.2.1/docs/releases/v1.2.1.md).
