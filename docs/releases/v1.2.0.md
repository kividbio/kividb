## What's in 1.2.0

1.2.0 is mostly about **not losing writes, and being a better Redis**:

- **Durability.**
  - With the append-only file on, a write is now acknowledged only once its record is in the file, as in Redis, so a killed process keeps every write it acknowledged.
  - A graceful shutdown (`SHUTDOWN`, SIGTERM) keeps every write it acknowledged: no command runs from the start of the final snapshot to the exit.
  - A transaction, or a script that writes more than once, reaches replicas and the AOF as one step, so a replica never shows it half done.
  - A manual failover whose election is slow no longer loses writes.
  - Automatic failover elects the replica with the most data.
- **Clusters.**
  - The bus keeps one connection per peer.
  - Nodes can announce a separate client port (`cluster-announce-client-port`), for NodePorts and load balancers.
  - After a failover, the shard's other replicas carry on instead of resyncing in full.
  - An import cut short by a restart cleans up after itself.
- **TLS without restarts.**
  - Certificates, CAs and `tls-port` change with `CONFIG SET`.
  - A server can turn TLS on while it runs.
  - `port 0` runs a server on TLS only.
  - `tls-auth-clients-allowed-names` accepts only client certificates whose names match.
- **Memory.**
  - Active defrag gives memory freed by deletes back to the system, and is on by default.
  - String values take less memory.
- **Search.** TEXT fields are stemmed, as in Redis: `preferences` finds `prefer`. Scores come out as Redis's, and `SCORER` is honoured. `FT.SEARCH` and `FT.AGGREGATE` take a `TIMEOUT`, and the timeout is safe across a rolling upgrade. Synonyms work. Scores stay right after updates and deletes.
- **Compatibility.** Dozens of fixes bring KiviDB's replies, errors, `INFO` and `CLIENT LIST` fields, keyspace events, Lua scripting and vector-set scores closer to Redis 8.10.
- **Signed releases.** Every file and image carries a signed build attestation. Check one with `gh attestation verify <file> --repo kividbio/kividb`.

[CHANGELOG.md](https://github.com/kividbio/kividb/blob/master/CHANGELOG.md) has the full list.

## Before you upgrade

- **Upgrade replicas before their master.** A 1.2.0 master sends transactions to its replicas wrapped in `MULTI`/`EXEC`.
  - A 1.1.x replica still applies their writes one by one, but logs two `ERR unknown command` warnings for each transaction.
  - A 1.2.0 replica of a 1.1.x master is fine.
  - The KiviDB Kubernetes operator already restarts a shard's replicas first and its master last.
- **No going back to 1.1.x once 1.2.0 has saved.** A snapshot holding a time series with compaction rules uses a format 1.1.x cannot read. Take a backup before you upgrade if you may need to go back.
- **With the AOF on, writes are slower.** Waiting for the record costs 20–28% of `SET`s a second with 50 clients, and under 10% with one client; reads cost nothing. `aof-ack-after-write no` gives 1.1.x's behaviour and speed back, at the cost of losing the last few acknowledged writes to a killed process.
- **Scripts: `pcall` and `assert` behave as in Redis.**
  - A script that read `e.err` from an error `pcall` caught finds the message in `e` itself now.
  - `assert` with a table as its message fails with `bad argument #2 to 'assert'`.
- **`CONFIG SET` refuses what it cannot set,** as Redis does. Unknown names, and settings that only take effect at startup, are now errors. Before, they replied `OK`. Settings that used to be ignored in the configuration file are now applied.
- **`AUTH <password>` is refused when no password is set,** as in Redis. Before, it said `OK`.
- **Search scores changed, to Redis's.** A word now also finds its other forms (stemming), and `WITHSCORES` / `ADDSCORES` values are Redis 8.10's: a TAG clause adds to the score, a field's `WEIGHT` counts each occurrence instead of multiplying the score. A threshold set on the old scores needs adjusting. `VERBATIM` on a query, or `NOSTEM` on a field, keeps the old matching.
- **`VSIM` / `VLINKS` scores are Redis's,** from 0 to 1 as `(1 + cosine) / 2`. A threshold an application set on the old scores, which went from -1 to 1, needs adjusting.
- **`activedefrag` is now on by default.**
- **A manual failover that cannot complete pauses writes for up to 10 seconds,** as in Redis. Before, the pause was 5 seconds, and writes could be lost.
- **Replicas with `tls-replication yes` tell their master their TLS port,** as Redis does, even when they also have a plaintext port.
