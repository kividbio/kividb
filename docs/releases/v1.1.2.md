## What's in 1.1.2

1.1.2 is a patch release of 1.1.0. It replaces 1.1.1, which has been
withdrawn for the expiry bug fixed here: if you run 1.1.1, upgrade. It
brings KiviDB in line with **Redis 8.10**, the release it reports
itself as. CI now runs Redis 8.10.2's own test suite against every change:
it went from 2079 tests passed, 76 failed and 7 units that hung or stopped
early, to 2697 passed and 6 failed, each of the 6 a documented difference
(see
[docs/REDIS_TEST_SUITE.md](https://github.com/kividbio/kividb/blob/master/docs/REDIS_TEST_SUITE.md)).
It also fixes a crash a crafted `RESTORE` payload could cause, keeps
function libraries across restarts and replication, loads far more of what
Redis writes, and makes the Linux packages run KiviDB as a service.

[CHANGELOG.md](https://github.com/kividbio/kividb/blob/master/CHANGELOG.md)
has the full list.

## Before you upgrade

- **The Docker image has no shell and no `redis-cli`.** It is now built on
  `gcr.io/distroless/cc-debian12`, which removes every critical CVE scanners
  reported on the 1.1.0 image. `docker exec <name> redis-cli` and `kubectl
  exec … -- redis-cli` no longer work; connect from another container
  instead (`docker run --rm -it --network container:<name> redis redis-cli
  -p 6380`), or with `kubectl debug` or a port-forward. The server still runs
  as UID and GID 1000 in `/home/kividb`, so existing volumes keep working.
- **The `.deb` and `.rpm` now install and start a systemd service.** 1.1.0's
  packages installed only the binary. Upgrading from them, or installing
  fresh, enables and starts `kividb.service`, which runs as the `kividb` user
  with its data in `/var/lib/kividb` and its config in
  `/etc/kividb/kividb.conf`, listening on `127.0.0.1:6380`. If you already run
  KiviDB from the packaged binary some other way on port 6380, stop that
  first or change the port in the config. A unit you have disabled stays
  disabled on later upgrades.
- **Function libraries are now kept in `dump.kdb`.** Before, `SAVE` and a
  restart, a clean stop with the AOF on, `BGREWRITEAOF` and a replica's full
  sync all dropped every library loaded with `FUNCTION LOAD`. In a rolling
  upgrade, a 1.1.2 replica that syncs from a 1.1.0 master gets no libraries,
  because the master's snapshot has none: upgrade the master (or fail over to
  an upgraded replica), then run `FUNCTION LOAD` once more, or `FUNCTION
  RESTORE` a `FUNCTION DUMP`. Going back to 1.1.0, its reader stops before
  the new section and starts without the libraries.
- **Replies and events that now follow Redis 8.10**, which a client written
  against 1.1.0 may notice:
  - `MSETEX` replies `1`, or `0` when `NX`/`XX` stops it (it replied `OK`
    or nil). `ARSCAN` and `ARGREP … WITHVALUES` reply with `[index, value]`
    pairs. `XINFO STREAM FULL` calls pending entries `pending` (was `pel`).
  - `HEXPIRE`, `HPEXPIRE` and the `EX`/`PX` of `HGETEX`/`HSETEX` take 0 as
    now and remove the fields; only a negative time is an error.
  - `SETEX` and `PSETEX` announce `set` then `expire` (they announced
    `setex`/`psetex`), and replacing a value announces the new `o`
    (overwritten) and `c` (type changed) events when those classes are on.
  - A script's error ends with the script and the place, `… script: <sha1>,
    on @user_script:1.`; `redis.error_reply('X')` is `-ERR X`.
  - `XADD … IDMPAUTO` hashes fields as Redis does, so an idempotent ID
    recorded by 1.1.0 does not match the same entry added again under 1.1.2
    until it leaves its retention window.
  - Arguments that were ignored or read loosely are refused with Redis's
    errors, and many error messages now use Redis 8.10's wording.
- **`EVAL` scripts and functions each have their own Lua VM**, as in Redis.
  `used_memory_lua` / `used_memory_vm_eval` now report the scripts' VM (it
  was always 0), and `used_memory_vm_functions` no longer includes it. If you
  alert on these figures, expect them to move.

## Security

- **A `RESTORE` could crash the server.** A payload whose string claimed a
  length near 2^64 made the server try to allocate it at once and abort; the
  checksum does not stop this, since anyone can compute one. A crafted RDB
  sent by a primary in a full sync could do the same. Such payloads are now
  refused with `ERR Bad data format`. This affects 1.1.0 and earlier: any
  client allowed to run `RESTORE` could stop the server.
- **`CONFIG REWRITE` keeps the config file's mode.** It wrote the file anew
  with the default mode, so a config kept at `0600` because it holds
  passwords became readable by every user.
- rustls 0.23.45 (GHSA-2mjx-qc3c-rqvc) and rand 0.8.6 (GHSA-cq8v-f236-94qc).
- Every release image is scanned with Trivy before it is published, and the
  published images and `Cargo.lock` are scanned again every week.

## Added

- **Data from Redis loads.** `RESTORE` of any Redis 6.2 to 8.10 payload,
  `MIGRATE` from a Redis server, a Redis `dump.rdb` at startup or from
  `--preload-file`, and a full sync from a Redis primary: strings, lists,
  sets, sorted sets, hashes (with per-field TTLs), streams (with consumer
  groups) and RedisJSON documents, in every encoding those versions write. A
  `dump.rdb` saved under an LRU or LFU policy, by a cluster node, with
  function libraries, or with the search module's index definitions loads
  too (indexes are not rebuilt: run `FT.CREATE` again; the log says so).
  `FUNCTION RESTORE` takes Redis 7.4 and 8.10 payloads.
- **Redis 8.10 additions:** `INFO keysizes`; keyspace event classes `o`, `c`
  and `a`; `XIDMPRECORD`; per-client traffic and command counters in `CLIENT
  LIST`/`CLIENT INFO`; `expired_keys_active`; `nacked-count`; VECTOR fields
  of `TYPE FLOAT64`, `FLOAT16` and `BFLOAT16`.
- **`UNLINK`, `FLUSHALL ASYNC`, `FLUSHDB ASYNC`, `FUNCTION FLUSH ASYNC` and
  `SCRIPT FLUSH ASYNC` free in the background**, counted in `INFO`'s
  `lazyfree_pending_objects` and `lazyfreed_objects`.
- **`CONFIG SET port` moves the listener** (it replied `OK` and kept the old
  port). `backup-sealed-ttl`, `stream-idmp-duration` and
  `stream-idmp-maxsize` take effect when set at run time.
- **`key-access-tracking yes`** keeps `OBJECT IDLETIME` and `FREQ` under
  every eviction policy, at about 500 instructions a command; `RESTORE …
  IDLETIME`/`FREQ` are applied.
- The `.deb` and `.rpm` bring a systemd unit, a `kividb` service user and a
  default config (see *Before you upgrade*).

## Fixed

- **Expired keys no longer pile up under a steady stream of writes with a
  TTL.** At about 90,000 `SET ... EX 20` a second on 8 vCPUs, the
  background expiry fell behind: keys past their time piled up, and memory
  grew without end (6.5 GB after three minutes, where Redis used 271 MB).
  Nothing was ever served past its time, but the memory was not given back.
  Now the keyspace stays at the keys that are live and memory is flat; on
  8 vCPUs expiry keeps up with about 200,000 keys coming due a second under
  load. Much faster than that (a pipelined load of about 600,000 a second)
  it still falls behind, which 1.2 is to lift. 1.1.0 has this too: a cache
  with TTLs should upgrade.
- **Nothing expires while writes are paused** (`CLIENT PAUSE`, a slot
  handoff, a manual failover), as in Redis; keys past their time expire and
  are announced once the pause ends. `expired_keys` is exact.
- **Clients a `CLIENT PAUSE` held go on first once it ends**, at once.
- **A message a connection publishes to itself comes after the reply** to
  the command that published it, and `SUBSCRIBE` inside `MULTI` is queued.
- **A `BCAST` tracking client is told only of the keys its user may read.**
- **A hash field whose time had passed came back from a snapshot as a field
  that never expires.**
- **Search:** a backslash in a TEXT field escapes the next character, as in
  Redis, which LangGraph's `RedisStore` relies on to keep namespaces apart;
  `MODULE LIST` names the built-in module families, so redisvl (and
  LlamaIndex's Redis vector store) connect.
- **Streams:** `XTRIM`/`XADD` trimming with `ACKED` skip an entry a group
  still needs instead of stopping; `XDELEX … ACKED` deletes from a stream
  with no groups; `XNACK`, `XACKDEL`, `XCLAIM … FORCE` and `XREADGROUP`
  follow Redis 8.10.
- **`CLIENT LIST`** reports real `idle=`, `qbuf` and `qbuf-free`, and an
  oversized query buffer is shrunk again.
- **`MEMORY USAGE`, `LATENCY GRAPH`, `COMMAND GETKEYS`, `ARINFO` and
  `ARRING`** report and behave as Redis 8.10 does.
- **HyperLogLog** caches its count in the value, as Redis does, and an
  `XREADGROUP` that changes nothing no longer counts as a change.
